## 작업 방식

사용자는 git 명령을 쓰지 않는다. GitHub Desktop 으로 Commit → Push 한다.

- 파일은 위 작업 폴더에 직접 고친다. 구글 드라이브 폴더(`G:\내 드라이브\클로드\wellclinic-report`)
  에도 예전 사본이 있지만 더 이상 쓰지 않는다.
- 빌드 검증은 임시 폴더에 복사해서 `npm run build` 로 한다. 드라이브 폴더나 저장소 안에서
  `npm install` 을 돌리지 않는다.
- 푸시하면 Vercel 이 자동 배포한다. 환경변수를 바꿨을 때만 수동 Redeploy 가 필요하다.

## 지금까지 만든 것

화면 여덟 개: 대시보드 · 일일보고 · 프로젝트 · 일정 · 월간보고 · 광고 성과 · 설정 · 알림
(알림은 왼쪽 메뉴에 넣지 않고 아래쪽 이름 옆 종 아이콘으로 들어간다)

- 일일보고: 작성자 선택(대리 입력 가능), 작성자별 필터, 같은 날 재저장 시 이어붙임.
  본문은 번호가 자동으로 매겨진다 (Enter 다음 번호, Tab 딸린 내용, Shift+Tab 되돌리기)
- 프로젝트: 상태·담당·마감·진행률, 상세 화면에 해당 프로젝트 업무 기록 타임라인
- 일정: 구글 캘린더 + 프로젝트 시작·마감 + 대한민국 공휴일. 화면에서 캘린더에 일정 직접 등록.
  일정을 누르면 구글 캘린더처럼 상세 팝업이 뜬다. 등록 시각은 30분 단위(`step=1800`)로만 받는다
- 알림: 일일보고·프로젝트·일정에 달린 코멘트를 모아 본다. 안 읽은 것이 있으면 사이드바 아래
  종 아이콘에 빨간 점이 찍힌다. 개수는 들어가서 본다
- 광고 성과: 일별/주별/월별 전환, 추이 그래프(자체 SVG), 캠페인별 지출, 채널별 매출, 청구 잔액
- 월간보고: 그달 일일보고와 광고 지표를 초안으로 자동 작성, 인쇄용 레이아웃

데이터는 `/api/ingest` 로 받는다. 토큰 인증이고 같은 날짜로 다시 보내면 덮어쓴다.

### 사람 명단은 코드에 있다

`src/lib/members.ts` 의 `ROSTER` 가 로그인·작성자·담당자 목록의 유일한 기준이다.
적은 순서가 곧 화면 순서라서 직급 높은 사람부터 적는다. 사람이 늘면 이 파일에 한 줄 넣고
Push 하면 끝이고, Vercel 을 만질 필요가 없다.

예전에 쓰던 `TEAM_MEMBERS` 환경변수는 더 이상 읽지 않는다. Vercel 에 값이 남아 있어도 무시되니
지워도 되고 그대로 둬도 된다.

### 코멘트와 알림

시트 탭 두 개를 쓴다. `코멘트` 는 대상종류(daily/project/event)·대상id·내용을, `알림확인` 은
사람마다 마지막으로 확인한 시각 한 줄을 담는다. 코멘트마다 읽음 표시를 두지 않는 이유는
행이 사람 수만큼 곱해져 시트가 금방 커지기 때문이다.

알림이 가는 규칙은 `src/lib/comments.ts` 의 `recipientsOf` 한 곳에 모여 있다.

| 코멘트를 단 곳 | 알림을 받는 사람 |
|---|---|
| 일일보고 | 그 보고를 쓴 사람 |
| 프로젝트 | 담당자 |
| 일정 | 전원 (일정에는 주인이 따로 없다) |
| 공통 | 같은 글에 이미 코멘트를 단 사람들. 자기가 쓴 코멘트는 자기에게 안 간다 |

## 겪었던 함정 (다시 밟지 말 것)

**구글 비공개 키의 줄바꿈**
`replace(/\\n/g, '\n')` 에서 역슬래시가 하나 빠지면 키 파싱이 통째로 실패한다.
`error:1E08010C:DECODER routines::unsupported` 가 그 증상이다. 지금은
`normalizePrivateKey` 가 따옴표·JSON 통째 붙여넣기·CRLF 까지 다 흡수한다.

**보고서 소계 줄이 캠페인으로 섞여 들어옴**
`__소계__`, `__합계__`, 매체 `전체` 같은 행이 시트에 들어오면 같은 금액을 두세 번 센다.
`isTotalLabel` / `isAggregateMedium` 이 걸러내지만, 수집 쪽에서 애초에 안 넣는 게 맞다.

**dbcart 랜딩이 4개**
스트라우만 하나만 보면 절반 넘게 빠진다. 랜딩변경 버튼은 누를 때마다 열림/닫힘이 바뀌므로
목록이 열렸는지 화면으로 확인하고 클릭해야 한다.

**구글 휴일 캘린더에 기념일이 섞여 있다**
설명란이 `공휴일` 인 것만 남긴다. `기념일` 은 국군의날·어버이날 같은 안 쉬는 날이다.

**bash heredoc 이 역슬래시를 하나 먹는다**
정규식이나 이스케이프가 들어가는 코드는 heredoc 대신 Write/Edit 도구로 쓴다.

**Sensitive 환경변수는 다시 볼 수 없다**
`INGEST_TOKEN` 등은 Vercel 에서 열람이 안 된다. 필요하면 새 값으로 교체한다.

## 남은 일

- **시트 탭 두 개 만들기**. 코멘트·알림 기능을 올린 뒤 배포된 사이트의 `설정` 화면에서
  `탭 만들기 · 확인` 을 한 번 눌러야 `코멘트`, `알림확인` 탭이 생긴다. 누르기 전에는
  코멘트를 남길 때 "시트 탭이 아직 만들어지지 않았습니다" 가 뜬다.
- **코멘트 저장 확인**. 코멘트·알림은 로컬에서 시트 없이 화면만 확인했다. 배포 후 실제로
  한 건 남겨 보고 시트에 행이 쌓이는지, 다른 사람 계정에서 종에 점이 뜨는지 봐야 한다.
- **직급 순서 확인**. 지금은 원장 → 부장 → 팀장 → 대리 → 사원 순으로 넣었다.
  원내 기준과 다르면 `src/lib/members.ts` 의 줄 순서만 바꾸면 된다.
- **서비스 계정 키 교체** (보안). 옛 키가 옵시디언 노트에 적혀 있었다. 노트에서는 지웠지만
  구글 클라우드에서 키를 새로 발급하고 옛 키를 삭제해야 실제로 무효가 된다. 절차는 SETUP.md.
- **옛 수집 루틴 정리**. 2026-08-21 09:41 에 무언가가 시트에 직접 써서 `__소계__` 형식 행이
  들어왔다. `/api/ingest` 를 거치지 않은 흔적이다. 예약 실행이 남아 있는지 확인이 필요하다.
- **제헌절·노동절 판단**. 구글이 둘 다 공휴일로 주는데 실제로 원내가 쉬는지에 따라 뺄 수 있다.
- **신규 DB 응대 여부**. 지금은 건수만 센다. 연락이 갔는지는 관리하지 않는다.
- **베트남 매출 탭의 내원 칸**이 비어 있어 내원율·동의율이 화면에 안 나온다. 시트를 채우면 된다.
