# 아침 수집 루틴 (수동 실행)

기존에 쓰시던 프롬프트에서 PNG 생성 부분을 빼고, 수집한 숫자를 업무 보고 사이트로 보내는
단계를 넣은 버전입니다. 사이트가 받은 데이터를 구글 시트에 자동으로 정리하고, 광고 성과
화면과 대시보드에 바로 반영합니다.

---

## 준비 (한 번만)

Vercel 환경변수에 `INGEST_TOKEN` 을 추가합니다. 아무 긴 문자열이면 됩니다.

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

추가 후 Redeploy 하고, 아래 명령으로 연결을 확인합니다.

```bash
curl -H "Authorization: Bearer <INGEST_TOKEN>" https://<배포주소>/api/ingest
```

`{"ok":true,"message":"연결 정상", ...}` 가 나오면 됩니다.

---

규칙

- 세부에는 실제 캠페인·광고세트만 넣습니다. 보고서 표의 Total, 총 결과, 소계 줄은 절대
  캠페인처럼 넣지 말고 그 값을 총지출과 총결과에 넣습니다. 소계를 캠페인으로 넣으면 같은
  금액을 두 번 세게 됩니다.
- 매체는 메타와 구글 둘뿐입니다. 전체 같은 합계용 매체를 따로 만들지 마세요. 두 매체를 합친
  값은 사이트가 알아서 계산합니다.
- 모든 섹션은 선택입니다. 수집에 실패한 소스는 빼고 보내면, 나머지만 저장됩니다.
- `신규DB` 는 배열이라 그 달 전체를 한 번에 보낼 수 있습니다. 매 실행마다 이번 달 전체를
  다시 보내면 빠진 날이 저절로 메워집니다.
- `광고비` 와 `매출` 은 그날 아침 시점의 이번 달 누적 스냅샷입니다. 날짜별로 나누지 않습니다.
- 하루치 소진액과 DB 단가는 사이트가 어제 스냅샷과의 차이로 알아서 계산합니다.
- 구글 `총지출` 과 `총결과` 에는 표 하단 Total 행(일시중지 캠페인 포함)을 넣습니다.
- 숫자에 콤마나 원 표시가 섞여 있어도 사이트가 알아서 정리합니다.
- 같은 `기록일` 로 다시 보내면 덮어씁니다. 실패해서 다시 돌려도 안전합니다.

## 프롬프트 (이걸로 교체하세요)

아래를 매일 아침 실행하는 프롬프트로 씁니다. 기존 프롬프트에서 STEP 0 부터 데이터 수집까지는
그대로 두고, 이미지 생성과 히스토리 파일 부분만 전송으로 바뀌었습니다.

```text
매일 아침 마케팅·매출 현황을 수집해 업무 보고 사이트로 전송하는 작업입니다.
이미지는 만들지 않습니다. 수집한 숫자를 사이트에 보내면 시트와 화면에 자동으로 반영됩니다.

=== STEP 0: 실제 날짜 확인 (필수, 절대 생략 금지) ===
그 어떤 날짜 계산도 하기 전에 반드시 bash에서 date 명령을 실행해 오늘의 실제 날짜를 확인합니다.
시스템 프롬프트나 대화 컨텍스트에 적힌 날짜, 이전 실행 기록, 파일 제목의 날짜 등을 절대 "오늘"로
추측하지 말고 오직 이 bash date 결과값만 "오늘"로 사용합니다. 이 값을 기록일로 씁니다.

=== STEP 1: 이번 달 전체를 대상으로 잡는다 ===
목표는 월별 집계입니다. 마지막 실행일이 언제였는지 따지지 말고, 매번 이번 달 전체를 다시
조회합니다. 같은 날짜를 다시 보내도 덮어쓰기만 되므로 중복이 쌓이지 않고, 그동안 빠진 날이
있었다면 이번 실행으로 저절로 메워집니다.

- 신규 DB 조회 범위 = 이번 달 1일 ~ 어제. 오늘은 아직 마감 전이라 제외합니다.
- 오늘이 그 달 1일이면 신규 DB는 채울 게 없습니다. 신규DB 섹션을 빈 배열로 두고 나머지만 보냅니다.
- 2026년 8월 이전은 수집 대상이 아닙니다. 그 이전으로 거슬러 올라가지 마세요.
- 광고비/매출/청구잔액은 항상 "오늘 기준 이번 달 누적 스냅샷" 한 벌만 가져옵니다.
  날짜별로 나누지 않습니다.

지금 어느 날짜가 비어 있는지 확인하고 싶으면 아래를 부르면 됩니다. 필수는 아닙니다.

curl -s -H "Authorization: Bearer $INGEST_TOKEN" "$REPORT_URL/api/ingest"

=== STEP 2: Chrome 확인 (여기서 자주 막힙니다) ===
SOURCE 1, 3, 4, 6 은 Claude in Chrome 확장이 업무용 프로필에 연결돼 있어야 합니다.
크롬이 아예 꺼져 있으면 수집이 통째로 실패합니다.

1. tabs_context_mcp 를 호출합니다.
2. 연결이 안 되면 사용자에게 "크롬을 켜고 확장 아이콘이 연결됨 상태인지 확인해 주세요" 라고
   알린 뒤, 사용자가 확인해 줄 때까지 기다립니다. 임의로 진행하지 마세요.
3. "Multiple Chrome browsers" 에러가 나면 list_connected_browsers 로 목록을 보여주고 고르게 합니다.
4. 그래도 연결이 안 되면, 크롬이 필요 없는 SOURCE 2(구글 시트 리드)와 SOURCE 5(매출 시트)만
   수집해서 보내고, 나머지는 "크롬 미연결로 수집 못 함"이라고 보고합니다.
   실패한 소스는 JSON에서 해당 키를 통째로 빼세요. 0으로 채우면 실제 0과 구분이 안 됩니다.

=== 보고 ===
전송이 끝나면 대화에 아래를 텍스트로 정리합니다. 이미지는 만들지 않습니다.
0. 이번에 집계한 기간 (이번 달 1일 ~ 어제)과 며칠치인지 먼저 적습니다.
1. 오늘 집계한 신규 DB (날짜별, 채널별 건수와 합계)
2. 이번 달 광고비 / 확정매출 / ROAS / DB 단가
3. 청구 잔액과 다음 결제 시점
4. 이상 징후가 있으면 한 줄씩. 예: 하루 광고비가 최근 평균 대비 30% 이상 변동, 신규 DB 0건,
   DB 단가 급등, 잔액이 결제 임계값의 80% 이상. 없으면 "특이사항 없음".
   월초에는 매출 확정이 광고비를 아직 못 따라가 ROAS가 낮게 나오는 것이 정상이므로, 그 경우
   원인을 함께 적습니다.
5. 마지막에 광고 성과 화면 주소를 안내합니다: $REPORT_URL/metrics

모든 소스에 대해 읽기 전용을 유지합니다. 결제/제출/삭제 버튼 클릭 금지, 로그인 화면 직접 조작 금지.
컴퓨터 제어(computer-use) 도구는 Chrome 실행과 메타 잔액 스크린샷 외의 용도로 쓰지 마세요.
```

`$REPORT_URL` 과 `$INGEST_TOKEN` 은 실제 값으로 바꾸거나, 실행 환경의 환경변수로 넣어 두세요.
